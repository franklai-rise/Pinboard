# Pinboard 0.7.0 验收记录

验收日期：2026-08-31

## 已通过

- Release 版编译成功，0 个编译警告、0 个编译错误。
- .NET 自动测试 45/45 通过，前端保存协议测试 9/9 通过。
- NuGet 与 npm 依赖漏洞扫描均为 0；前端 TypeScript/Vite 构建成功。
- Windows x64 自包含单文件发布和 ZIP/SHA-256 打包成功。
- 自动测试覆盖 Text Clips、隐私默认值、敏感格式过滤、默认英文、PixPin 快捷键观察器、WebP、SQLite、截图布局、搜索、项目、恢复点、OCR 与导入。
- 画板数据库升级为 schema v2；当前场景与恢复点使用 Brotli 压缩，v1 画板在单一事务中迁移。
- 新增保存 revision 冲突保护、主机确认回执和外部截图/文字投递锁，避免旧画布覆盖新收录内容。
- 恢复点列表、恢复和安全精简 API 已实现；资源回收会保留当前场景及保留恢复点中仍引用的图片。
- 文字索引改为增量更新，3 字符及以上查询使用 FTS5，短关键词自动回退普通匹配。
- WebView2 只允许内置 `app.pinboard` 资源，拦截外部导航、子框架与网络请求。
- 单实例通信限制为当前 Windows 用户且限制消息大小；异常日志仅在本机轮换保留。
- 全新安装默认关闭文字收集和窗口置顶；旧用户的明确设置保留，已开启文字收集的旧设置会提示隐私复核。
- 便携版后台启动冒烟测试通过：进程正常响应，内置 WebView2 画布资源成功解包。
- `.pinboard` 使用 SQLite `DELETE` 日志与完整同步；正常关闭事务后没有长期 `.wal` / `.shm` 边车。
- 8 月迁移：5 个图片元素、5 个内嵌 WebP，其中 1 个为原文件已有的空 Markdown 图片占位；4 张真实截图完成中英文 OCR。
- 9 月迁移：9 个图片元素、9 个内嵌 WebP；9 张真实截图完成中英文 OCR。
- 两个月共 13 张真实截图全部迁移，原 Obsidian Vault 未修改。
- 新画板文件可从单个 `.pinboard` 文件读取场景、图片与搜索索引，不依赖原 `_media`。
- 文件关联、`pinboard://` 协议、单实例转发、托盘接收、120 秒剪贴板监听与失败恢复路径已实现。
- PNG、SVG、标准 `.excalidraw` 导出以及 Obsidian/标准 Excalidraw 导入已实现。
- 左侧项目画板栏、独立新建项目、空项目显示、项目内新建、画板移动、固定名称排序、当前项高亮、侧栏收起状态记忆与窗口置顶状态记忆已实现。
- 中英文即时切换、默认英文、语言选择持久化以及 Excalidraw 工具栏同步切换已实现。
- 画板显示名称与磁盘文件名已分离；右键菜单可显示、复制并在资源管理器中定位真实路径。
- 画板右键菜单新增“归档画板 / 恢复到项目”和“移到回收站”；归档默认收起显示在侧栏底部，删除采用 Windows 回收站而非直接永久删除。
- 关闭窗口后会隐藏到系统托盘，不再遗留任务栏窗口；单击托盘图标或桌面快捷方式可恢复窗口，避免只能从托盘菜单进入。
- Pinboard 在后台仅观察 PixPin 的普通 `Ctrl+Alt+A`（不占用快捷键）；下一张通过 Enter、Ctrl+C 或复制按钮写入剪贴板的截图会自动保存到当月画板，取消或未复制的截图不会生成空白内容。
- 自动收录的截图会按两列瀑布流错开分布，始终投放到较短的一列并保留 64 画布像素间距；已有截图位置不受影响。
- Pinboard 默认注册为当前 Windows 用户登录后的后台启动项（`--background`），在系统托盘静默运行；设置页可随时开启或关闭该项。
- 修复 Windows 恢复最大化窗口状态时，后台启动与 `ShowActivated=false` 发生冲突而无法启动的问题。
- 左侧固定接收画板采用紫蓝炫光边框和“接收中”标记；在任意画板的 `⋯` 或右键菜单可一键切换截图接收目标，也可恢复自动月度目标。
- Windows 剪贴板普通文字会自动收录到项目库根目录的 `Text Clips.pinboard`；每段内容以带时间戳的浅色卡片纵向排列，长文本会自动换行，原始文字可参与当前和跨画板搜索。
- 文字收集与 PixPin 截图接收互不干扰；全新安装默认关闭。图片和文件拖放不会进入 Text Clips，Pinboard 自身复制操作会被排除。设置页提供独立暂停、常见敏感格式过滤和尽力而为的应用排除。

## 需要用户完成的一次性交互

- 普通 `Ctrl+Alt+A` 自动收录不需要修改 PixPin 配置；可选 `Ctrl+Alt+P` 动作仍需用户在 PixPin 界面中粘贴脚本，因为 PixPin 的自定义动作内部持久化键没有公开稳定格式。
- 完整的“真人框选、复制截图、取消截图、通知点击”流程依赖交互式桌面，发布前只对快捷键观察器、接收器、协议、数据库与后台启动进行了自动/冒烟验证；首次使用建议分别做一次正常截图复制和一次取消截图。

## 已知限制

- 第一版不做账户、同步、协作、手机端、内置截图或自动更新。
- Windows OCR 的识别准确率取决于系统语言包和截图质量；OCR 失败不影响图片保存。
- 自动文字收集按 Windows 剪贴板变化工作；隐私过滤和应用排除不是绝对保证，复制密码或私密信息前应暂停文字接收。
- 大型画板首次打开时需要把内嵌图片送入 WebView2，200 MB 极限场景的实际耗时取决于磁盘和内存，当前未在真实 200 MB 用户画板上做完整基准。
- v1 画板首次被 v0.7.0 以可写方式打开后会升级为 v2；旧版 0.6.x 不能再打开该副本，升级前应保留备份。
- 原 Obsidian 中的空 `markdown-image` 元素会显示为静态占位图；其余 13 张 PNG 已完整迁移。

## 恢复方式

- 正常备份：使用“保存副本”，或在关闭编辑后复制单个 `.pinboard`。
- 自动恢复：查看 `%LocalAppData%\Pinboard\Recovery`。
- PixPin 配置：先退出 PixPin，再在“设置 → PixPin 集成”中恢复由 Pinboard 创建的最近备份。
- 导入不会删除、移动或修改来源画板；确认迁移结果前请保留自己的原始资料备份。
